A chat window on a website feels like progress. Someone asks a question and gets a paragraph back. The test that matters is what happens after the paragraph. If a person still has to retype the request into a CRM, a booking sheet or a ticket queue, you have a chatbot. If the allowed next step is already done in the system of record, you have an agent.

That distinction is practical, not a branding choice. Both tools can use a large language model. Both can sound fluent. Only one of them is permitted to change something.

## What a chatbot is good at

A chatbot is the right tool when the job is to explain. Course descriptions, opening hours, a policy page, the difference between two plans. The source is a document or a set of pages you control, and the success condition is a clear answer.

It is also the right tool when you are not ready to let software touch a record. If your data is inconsistent, or nobody has agreed what “confirmed” means, a chatbot that says “a colleague will follow up” is more honest than an agent that writes a confident wrong status.

The failure mode is familiar. The reply is polite, the visitor thinks the work is finished, and the team finds the request the next morning inside a transcript nobody owns.

## What changes when the software may act

An agent is a chatbot plus a short list of actions. Check an application status. Create a support ticket. Hold a published room rate. Send the confirmation you already send by hand. Each action has an input, a system it calls, and a result the person can see.

The list should be boringly specific. “Help the customer” is not an action. “Look up the booking by phone number and read back the arrival date” is an action. “Create a follow-up task assigned to the admissions desk” is an action. Anything you cannot write in that form stays with a person.

Write the refusals down as well. An admissions agent does not grant a fee waiver. A hotel agent does not invent a rate that is not in the availability rules. A support agent does not close a complaint that needs a manager. The handoff should include what the person already said, so the team does not start the conversation again.

## A test you can run on paper

Before you connect a model to anything, walk one real request on a whiteboard.

1. The person asks for something you handle every day.
2. The agent is allowed to read one kind of record.
3. It either completes one named action or it stops and assigns a person.
4. The record now shows the new status, and the person gets that status back.

If step 4 still requires someone to copy from the chat into another tool, you have not built an agent yet. You have built a nicer inbox. That can still be worth doing, but name it honestly so the project does not claim a result it cannot produce.

## Where the agent has to live

The agent is only as trustworthy as the system behind it. If WhatsApp, the website and the CRM disagree about a lead, the agent will disagree with itself depending on which tool it calls. Connect the record first, or give the agent exactly one place to read and write.

Voice and WhatsApp can share those rules. A caller and a chat user should not receive two versions of a status because the channels were built as separate projects. The channel collects the request. The system decides.

## A sensible first scope

Pick one action that your team already performs the same way every time, and that is painful only because it is repeated. Status lookups are a common first action because they do not change money, seats or clinical decisions. Creating a ticket is another, if the queue and the required fields are already agreed.

Leave judgment calls for later: discounts, exceptions, anything a senior person would pause on. An agent that handles the repetitive path, and visibly hands over the rest, is more useful than one that tries to sound like it can run the business.

When you are ready to talk through a real workflow, start from the action list rather than from the model. The model is replaceable. The list of what software is allowed to do is the product.
